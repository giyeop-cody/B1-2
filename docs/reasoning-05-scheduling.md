# 추론 기록 #05: 스케줄링 알고리즘 추론 (보너스)

## 관측 대상
MULTI_THREAD_ENABLE=false, "Healthy System Monitoring" 시나리오의 스레드 실행 로그

## 분석 과정

### 로그 패턴
```
14:46:27.648 [Thread-A] Started → (20→40→60→80→100%) → Completed
14:46:27.902 [Thread-B] Started → (20→40→60→80→100%) → Completed  ← A 완료 후 시작
14:46:28.156 [Thread-C] Started → (20→40→60→80→100%) → Completed  ← B 완료 후 시작
14:46:28.409 [Scheduler] All tasks completed.
```

### 후보 알고리즘 검증
| 알고리즘 | 순차처리 | 비선점 | 등록순 | 타임퀀텀 | 일치 |
|----------|---------|--------|--------|---------|------|
| FCFS | ✅ | ✅ | ✅ | 없음 | ✅ |
| Round-Robin | ❌ | ❌ | 부분 | 있음 | ❌ |
| Priority | ✅ | ✅ | ❌ | 없음 | ❌ |

### 핵심 판단 근거
1. Thread-A가 100% 완료 후에만 Thread-B 시작 → 비선점 + 순차
2. 등록 순서(A,B,C) = 실행 순서 → FCFS
3. Round-Robin의 컨텍스트 스위칭(시간 할당량 교체) 관측 안 됨

### 결론: FCFS (First Come First Served)

## 적합성 분석
| 서비스 | 적합 | 이유 |
|--------|------|------|
| 배치 처리 | ✅ | 처리량 중심, 순서 보장 |
| 웹 서버 | ❌ | convoy effect로 응답 지연 |
| 로그 파이프라인 | ✅ | 순서 보장 중요 |

## 응용
- 스케줄링 추론 프레임:
  1. 로그 타임스탬프로 실행 순서 추출
  2. "완료 전 교체 여부" → 선점/비선점 판별
  3. "시간 할당량 존재 여부" → Round-Robin vs FCFS 판별
  4. "우선순위 정렬 여부" → Priority 판별
  5. 장단점 + 적합 서비스 분석
