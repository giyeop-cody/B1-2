# 동시 장애 우선순위 결정 매트릭스

> 사전평가 #18 FAIL 대응: 동시 장애 발생 시 우선순위 결정 기준, 근거, 절차 문서

## 1. 배경

B1-2 과제에서 OOM, CPU Spike, Deadlock 3가지 장애 유형을 개별 분석했다. 하지만 실서버에서는 여러 장애가 동시에 발생할 수 있으며, 이 경우 **어떤 장애를 먼저 조치할지** 결정하는 기준이 필요하다.

## 2. 우선순위 결정 기준

| 기준 | 설명 | 측정 방법 |
|------|------|-----------|
| **서비스 영향도** | 장애가 사용자/비즈니스에 미치는 피해 정도 | 응답 지연, 요청 실패율, 데이터 손실 가능성 |
| **확산 속도** | 장애가 시스템 전체로 퍼지는 속도 | 메모리/CPU 점유 증가율, 연쇄 장애 여부 |
| **복구 난이도** | 조치 후 정상 상태로 복귀하는 소요 시간/비용 | 재시작 필요 여부, 데이터 복구 필요성 |

## 3. 장애별 평가

| 장애 유형 | 서비스 영향도 | 확산 속도 | 복구 난이도 | 종합 점수 | 우선순위 |
|-----------|--------------|-----------|-------------|-----------|---------|
| **OOM (Memory Leak)** | 높음 (프로세스 즉시 종료 → 서비스 중단) | 중간 (선형 증가, 수십초~분 단위) | 낮음 (환경변수 조정 또는 재시작) | **높음** | **1순위** |
| **CPU Spike** | 중간 (응답 지연, 타임아웃 유발) | 빠름 (비선형 급증, 수초 단위) | 낮음 (환경변수 조정 또는 재시작) | **중간** | **2순위** |
| **Deadlock** | 높음 (프로세스 무응답 → 서비스 중단) | 느림 (즉시 멈추지만 확산 없음) | 중간 (스레드 설계 수정 필요, 환경변수로 임시 회피) | **중간** | **3순위** |

### 점수 산정 근거
- **OOM 1순위**: 프로세스가 **종료**되어 서비스가 완전히 중단됨. 데이터 무결성 위험 (진행 중 트랜잭션 손실). MemoryGuard는 시스템 보호이지만 서비스 관점에서는 치명적.
- **CPU Spike 2순위**: 프로세스는 **종료되지만** 응답 지연이 먼저 발생하여 사용자 경험 저하. Watchdog 종료 전에 타임아웃/지연이 먼저 관측됨.
- **Deadlock 3순위**: 프로세스가 **종료되지 않고 멈춤** 상태. PID는 살아있으므로 헬스체크가 통과할 수 있어 탐지가 늦을 수 있음. 하지만 확산은 없음.

## 4. 동시 발생 시 조치 절차

```
동시 장애 감지 (모니터링 알림)
    │
    ├── 1단계: 장애 식별 (ps/top/log 동시 수집)
    │   ├── 프로세스 종료? → OOM 또는 CPU Spike 의심
    │   ├── 프로세스 살아있으나 무응답? → Deadlock 의심
    │   └── CPU 급증 + 메모리 급증? → OOM + CPU 동시 발생 가능
    │
    ├── 2단계: 우선순위 적용
    │   ├── OOM 감지 → 즉시 조치 (1순위)
    │   │   └── MEMORY_LIMIT 상향 → 재시작 → 서비스 복구
    │   ├── CPU Spike 감시 → OOM 조치 후 조치 (2순위)
    │   │   └── CPU_MAX_OCCUPY 하향 → 재시작
    │   └── Deadlock 감지 → CPU/OOM 조치 후 조치 (3순위)
    │       └── MULTI_THREAD_ENABLE=false → 재시작
    │
    ├── 3단계: 임시 조치 후 근본 원인 분석
    │   ├── 스택 트레이스 캡처 (Deadlock)
    │   ├── 메모리 프로파일링 (OOM)
    │   └── CPU 플레임그래프 (CPU Spike)
    │
    └── 4단계: 근본 해결 + 회고
        ├── 코드 수정 (메모리 해제, 락 순서 통일, CPU backoff)
        └── 회고 문서 작성 (재발 방지 대책)
```

## 5. 의사결정 매트릭스 (빠른 판단용)

| 상황 | 즉시 조치 | 이유 |
|------|-----------|------|
| 프로세스 종료 + 메모리 로그 | OOM 조치 (MEMORY_LIMIT↑) | 서비스 중단 + 데이터 손실 위험 |
| 프로세스 종료 + CPU 로그 | CPU 조치 (CPU_MAX_OCCUPY↓) | 서비스 중단이지만 데이터 손실 적음 |
| 프로세스 무응답 + 로그 중단 | Deadlock 조치 (MULTI_THREAD=false) | 탐지 지연 가능, 확산 없음 |
| 종료 + 무응답 혼재 | OOM 우선 → Deadlock 차선 | 서비스 영향도가 최우선 |

## 6. 응용
- 이 매트릭스는 agent-leak-app에 국한되지 않고, 일반적인 프로세스 장애 우선순위 결정에 적용 가능
- 서비스 특성에 따라 가중치 조정: 실시간 서비스 → 응답 지간(=CPU) 우선, 배치 서비스 → 데이터 손실(=OOM) 우선
