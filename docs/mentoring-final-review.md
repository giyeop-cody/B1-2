# 최종 검증 학습 멘토 토론 기록

- 날짜: 2026-08-16
- 주제: 파일이 있다는 것과 증명했다는 것은 같은가

## 학생

`stacktrace.txt`라는 파일이 이미 있으니 스택 트레이스를 제출했다고 말해도 되지 않나요?

## 멘토

파일 이름보다 안의 내용이 중요합니다. 기존 파일은 `/proc`의 대기 상태였고, 평가자는 gdb 또는 pstack의 실제 사용자 영역 호출 프레임을 요구했습니다. 그래서 실제 실행 중 gdb를 attach해 `thread apply all bt`를 저장해야 합니다.

## 학생

gdb 결과에 `Shared_Memory_A`와 `Socket_Pool_B`가 안 나옵니다. 그러면 실패인가요?

## 멘토

바이너리가 stripped 상태라 내부 이름이 안 나올 수 있습니다. 없는 이름을 만들면 안 됩니다. 대신 증거의 역할을 나누세요.

- 앱 로그: 어떤 이름의 락을 보유·대기하는지
- `ps -T`: 스레드들이 계속 futex 대기인지
- gdb: 실제 사용자 영역에서 lock 획득 경로에 있는지

세 자료가 같은 시각의 같은 실행을 가리키면 더 정직하고 강한 설명이 됩니다.

## 학생

OOM After에서 CPU도 100이면 왜 문제인가요?

## 멘토

Memory 효과를 보려는데 CPU Watchdog이 먼저 종료할 수 있습니다. 과학 실험처럼 비교할 값 하나만 바꿔야 합니다. 그래서 OOM은 CPU=50과 Thread=false를 고정하고 Memory만 256→512로 바꿨습니다.

## 결론

- 증거는 파일명이 아니라 실제 내용으로 판정한다.
- 비교 실험은 변수 하나만 바꾼다.
- 도구가 보여주지 않은 내용을 보여준 것처럼 쓰지 않는다.
- 자체 검증과 공식 평가를 구분한다.
