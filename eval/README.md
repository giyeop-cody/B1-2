## 평가 시 지켜야 할 구분

1. **실측**: 이번 실행에서 직접 확보한 로그·메타데이터·스택.
2. **해석**: 실측에 기반한 원인 추론. 앱 로그의 자원 소유 관계와 실제 스택 대기를 함께 설명한다.
3. **제안**: 운영 적용·코드 수정 아이디어. 구현하거나 검증한 것처럼 말하지 않는다.

기존 실험은 after를 170초 관측하고 정리했다. 따라서 “영구 해결” 또는 “무중단 검증 완료”로
답변하지 않는다. CPU의 내부 Load와 OS 사용률은 별도 원본으로 제시하고,
보너스는 앱의 실제 SCHED_OTHER/nice와 대조 실험에 기반해 Priority 계열의 가중 공정 배분으로
추론한다. 순환 출력만 보고 실시간 SCHED_RR이라고 주장하지 않는다.

## 재실행을 요청받으면

현재 원본 증거를 먼저 보여 준다. 재실험은 약 13분 이상 걸리고 실습 VM의 앱·로그를 변경한다.
평가자가 실제 재현을 요청할 때만 [재현 절차](../docs/reproduction.md)에 따라 실습 머신에서
`scripts/run-experiments.sh`를 실행한다. 새 로그는 `rerun-evidence/`에 저장한다.
이 실행기는 B1-1을 자동 원복하지 않으므로 종료 후 선행 환경의 원복 절차를 수행해야 한다.
